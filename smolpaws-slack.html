SmolPaws Slack Coordinator Canary canary

A greenfield Slack bridge for proving the durable SmolPaws message-work architecture.
Source: apps/slack/  ·  Relay: outboundRelay.ts  ·  Dispatcher: deliveryDispatcher.ts

Authority: current code, executable tests, the agent-server EventLog, and coordinator SQLite records. This page describes the architecture. It deliberately does not treat a visible Slack reply alone as proof that a local process is running the newest canary.

Current architecture

apps/slack is intentionally greenfield. It runs as a standalone Socket Mode process, owns its Bolt connection and Slack coordinator runtime directly, and does not inherit BaseBridgeAdapter, join the shared bridge loader, or fall back to the legacy /turns path on port 8788.

Why syncDeliveryOutbox()?

The Relay repeatedly catches a conversation up from its durable agent-event cursor. For the first Slack canary, the normal terminal agent response becomes one durable delivery row. Repeating the sync is safe because the source identity combines the originating event and destination lane.

agent event id + destination lane
              ↓
unique delivery source_key
              ↓
replay becomes a no-op

The name is intentionally plainer than “projector”: the method synchronizes an outbox. It does not itself contact Slack.

Delivery semantics

The Dispatcher validates work before the external boundary. Immediately before calling Slack, it durably sets send_attempted = true.

SituationOutcome
Invalid payload or no registered targetKnown failed work before any network send
Claim expires before a send attemptSafe to make ready again
Exception after the send fencedelivery_unknown; never blindly retry
Slack confirms the messagedone with Slack ts as external_message_id

Idempotency boundaries

  • Coordinator SQLite, keyed by stable Slack message identity, is the durable intake authority.
  • The in-memory duplicate gate only suppresses simultaneous or very recent callbacks.
  • A failed durable acceptance releases that gate immediately, before a best-effort Slack error reply.
  • Deterministic agent event IDs make append-response loss safe to replay.
  • Unique delivery source keys make outbox catch-up safe to replay.

Canary proof

A valid Liberty Labs canary establishes all of the following:

  1. The running checkout identifies the intended candidate commit.
  2. The TypeScript agent-server on port 8790 is healthy.
  3. The triggering event has an intake row that reaches done.
  4. The server EventLog contains the deterministic user event and terminal agent output.
  5. syncDeliveryOutbox() creates a corresponding delivery row.
  6. The Dispatcher settles it done with the Slack message timestamp.
  7. The reply appears in the correct DM or thread exactly once.

A response containing 🐾 Done — nothing to report back. identifies the old BaseBridgeAdapter//turns fallback. It is not proof of the Relay canary.
