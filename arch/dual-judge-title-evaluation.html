Title experiment three · 30 October 2026

One title format.
Two independent judges.

A fixed “Topic — action” prompt combines consistent structure with meaningful differences. Codex and Jev independently classify the same displayed titles and sibling collections. Their disagreements remain visible; neither is treated as ground truth.

288 generations · 217 unique title texts for judging · 48 collections

First experiment · Topic-first follow-up — both unchanged.

Four instructions, plus a fidelity gate.

  1. Make the task clear.
  2. Put distinguishing topic words first.
  3. Keep parallel structure and meaningful distinctions together.
  4. Preserve connotation when sentiment matters.

“Make variation meaningful” is merged with collection consistency. It remains part of the evaluation. Requested-work fidelity is a separate requirement: a polished title still fails if it changes the task.

Exact fixed-format prompt
Write one conversation title of at most {max_length} characters, including one relevant emoji. Use this exact layout: EMOJI Topic — action. Keep it near 42 characters by choosing shorter words, never by cutting a word. Rules:
1. Make the requested work clear and faithful. Keep status, uncertainty, negation, and who expressed a view. Investigation is not repair; a proposal is not approval; summarizing customer praise is not praising the subject yourself. Never invent completion.
2. Put the distinguishing topic in the first two meaningful words after the emoji.
3. Use a parallel topic/action structure and stable terms for equivalent requests. Let different topics and genuinely different actions create the differences, not random wording.
4. When relevant, preserve complaint, praise, mixed, or neutral intent.
Use short action labels such as investigate, upgrade/test, explain, summarize feedback, draft proposal, or write note, only when accurate. Return only the title.

USER REQUEST:
{conversation_content}
Exact shared scoring rubric
Clear task

Does this displayed title clearly convey an understandable task or topic? Imperative, noun phrases and topic—action labels are all allowed. Ignore harmless clipping of a modifier when the core task remains clear.

{
  "fail": "The core task is unclear or incoherent.",
  "partial": "The core task is partly understandable but its main clause is incomplete or grammatically ambiguous.",
  "pass": "The core task is clear and understandable."
}
Topic first

Do the first two meaningful lexical words after the emoji identify the distinguishing topic of this request? Ignore punctuation, not ordinary action words; the state includes the exact first two words computed in code.

{
  "fail": "The displayed title does not identify a useful distinguishing topic.",
  "partial": "The topic is clear but appears after the first two meaningful words.",
  "pass": "The distinguishing topic appears in the first two meaningful words after the emoji."
}
Requested-work fidelity

Does the title preserve the requested work without an actual wrong action, invented completion/decision, reversed negation, false certainty, or changed attribution? Omission of minor details is allowed. A title naming an inspection or test is compatible with explaining that activity unless it explicitly claims execution or completion. Reporting a completed fix can be factually true but failing to mention writing the requested release note is loss of requested work.

{
  "fail": "The title misstates requested work or makes a misleading claim, including praising rather than summarizing customers’ praise.",
  "pass": "The title describes the requested work or a compatible concise topic without a misleading claim."
}
Connotation

For these customer-feedback or neutral-comparison requests, does the title preserve the input’s sentiment without inventing endorsement or a preference? Explicit mixed feedback counts as both-sided. Generic feedback loses polarity but does not reverse it.

{
  "fail": "The title reverses or invents sentiment or preference.",
  "partial": "The title becomes generic/neutral and loses a useful positive, negative or mixed distinction.",
  "pass": "The title preserves the relevant complaint, praise, mixed feedback or neutral comparison intent."
}
Consistent, meaningful collection

Judge the sibling titles together. Equivalent requests should use parallel topic/action grammar and stable action terms; meaningful differences in topics or requested actions must remain distinguishable. Ignore emoji, punctuation and compatible abbreviations such as Tests/Regression Tests. A fixed-format label is not required for default titles.

{
  "fail": "Equivalent tasks use substantially inconsistent structures, or a meaningful distinction is lost or replaced with invented work.",
  "partial": "Subjects remain distinguishable but there is some arbitrary structural, vocabulary or specificity variation.",
  "pass": "The collection uses parallel structure/stable terms for equivalent tasks and preserves justified topic/action differences."
}

Format is measured in code, not by either judge: the em-dash layout occurred in 144/144 fixed-prompt titles and 0/144 default titles. This check does not prove that the topic or action is correct.

Both judges favor topic-first. Collections divide them.

Shared finding: the fixed format improved front-loading: Codex 107/144 → 144/144; Jev 102/144 → 141/144. Both gave all 144 fixed-format titles a fidelity pass. These are classifier judgments on the tuned set, not proof of correctness.

Unsettled: collection passes moved in opposite directions. Codex: 15/24 → 13/24. Jev: 17/24 → 19/24. The judges agreed on only 30/48 collection grades. I would inspect those disagreements before changing the SDK default.
