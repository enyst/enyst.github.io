The swap, step by step

  1. Swap in openhands-agent for the old SDK → next

    Point the server at @smolpaws/openhands-agent instead of the old @smolpaws/agent-sdk — the new SDK becomes the engine. Doing this first surfaces exactly what the server actually relies on, which then scopes step 2. Not begun; the SDK it depends on is landing (dispatcher merged, persistence in review).

    unblocks: scope of step 2
  2. Agent-server parity (ish) ◐ in progress

    Transpile the upstream openhands-agent-server to TS so the new SDK has a server to run on. First slices landed — event/conversation routers, event & conversation services, pubSub, sockets, OpenAPI, plus bash/git/file routers. Durability now flows through the SDK's EventLog (server is a thin wrapper, like upstream). Still ahead: remaining routers (P2/P3) and the message-queue layer. Final scope follows what step 1's cutover reveals.

    pkg: smolpaws/packages/openhands-agent-server verified green: 227 SDK tests · server build/test/openapi ✓
  3. Redesign bridges without turns → message queue ○ the hard design

    The hard part. Retire the bespoke turns abstraction and rebuild its three guarantees (exactly-once delivery, idempotency, ordering) on a lean local-first queue. Several existing bugs are really symptoms of turns papering over this — they should die with the redesign.

    smolpaws-e4j orphaned replies smolpaws-109 duplicate replies smolpaws-7dj out-of-order outbound smolpaws-6qo send_message not delivered smolpaws-0de shared scheduler layer
  4. Swap agent-server + WhatsApp (keep the lifeline) ○ not started

    Smallest end-to-end slice that lets Engel and SmolPaws keep talking on the new stack. Everything after this happens with the lifeline intact.

    depends on: steps 2–3
  5. Then Discord, GitHub, Email ○ not started

    Migrate the remaining bridges onto the queue model — repeats of a known move (they share the adapter base).

    smolpaws-3iy GitHub webhook dedup smolpaws-z3l whitelisted-thread listen
  6. Slack-via-Chrome should keep working untouched ○ verify later

    The heartbeat Slack reading goes through the browser, not the agent-server, so the swap shouldn't touch it. Confirm once the new stack is live.

  7. Retest / adapt / redeploy paws (standalone Slack app) ○ not started

    The separate Slack bot app rides the agent-server via the bridge adapter. Not in active use yet, but it will be; it goes last and carefully.

    smolpaws-c6q Slack ingress smolpaws-c6s Socket Mode delivery smolpaws-c6r / c6t / c6u scaffold · context · ops
