Where to put it in OpenHands #

A read-only inspection of local Canvas and Cloud definitions informed the recommendations. The existing workflow families include attention routing and notebook selection, duplicate detection, QA validation, test-quality sweeps, upstream porting, and fast security auditing. This public page describes integration opportunities; private prompts, account identifiers, endpoints, and run records are omitted.

Code decision: priority_verification

The paired locked recheck dropped TOCTOU from 0.76 to 0.10; the path check/open pair scored 0.83 versus 0.11 for verified-descriptor use. Remote install execution scored 0.98 while download-only scored 0.07. These obvious fixtures exercise discrimination and benign exceptions; they do not estimate detection rates for subtle real vulnerabilities.

How to verify a flagged TOCTOU: identify the checked invariant, mutator and use; introduce a controlled barrier between check and use; mutate state; compare old and fixed behavior. For cancellation, hold the resource lock, queue a tool, cancel it, release the lock, and verify that the side effect never runs. For supply-chain risk, trace trigger → checkout revision → install hooks → token permissions; inspect pinned workflow and lockfile data without executing untrusted installs. Report evidence scope and missing callers.

A calibration plan for OpenHands #

  1. Define the target first. Label investigation actionability, correct owner, concrete TOCTOU evidence, supply-chain evidence, and reviewer usefulness separately. Have disputed cases adjudicated. Record missing references and collector truncation separately from negative labels.
  2. Split by related work. Keep duplicate issues, PR revisions and examples from the same incident together; reserve a later or otherwise held-out test set. Use a separate tuning/calibration split for wording, method selection and thresholds. Our small, hand-built fixture set cannot fill all these roles.
  3. Compare mappings. Fit isotonic and a logistic baseline on calibration data only. Evaluate Noul against event labels; evaluate Choice selection against correctness. For relevance, retain the ordinal ranking and assess usefulness at the review budget rather than pretending a normalized Score is a probability.
  4. Evaluate the actual action policy. Report reliability bins with counts, Brier score, log loss, class/tier results, and accepted-decision error versus coverage with uncertainty bounds. Security additionally needs recall on confirmed positives and investigation load. A low average calibration error can hide rare, costly misses.
  5. Version the whole setup. Save model ID, question wording, option order/descriptions, preprocessing, label policy and calibrator. Revalidate changes and population drift. Sufficiency plus owner confidence are not independent guarantees; do not multiply them to claim workflow reliability.

Next experiments: retrieval and model routing #

Memory/context reranking: freeze a set of real questions with independently labeled useful passages. Compare the current retriever with retriever → Jev Score → top-k passages, under the same final context budget. Measure recall@k, downstream task success, retained constraints, added latency and total cost. Include stale notes, contradictory passages and embedded instructions. Mandatory task constraints stay outside this optional ranking step. The vendor’s reranking cookbook demonstrates the architecture on legal passages; it does not establish gains for OpenHands memory.

Model-profile routing: run the same bounded tasks under the current default profile and under Jev’s proposed routing, initially without changing production selection. Measure verified task success, retries, escalation rate, wall time and total spend including the router. Only save money when downstream quality survives; a confident difficulty estimate is not a measured capability result. The vendor’s routing pattern is useful design guidance, not an OpenHands benchmark.

The current model input contract rules out direct screenshot perception. For both new experiments, freeze the model and rubric, separate tuning from held-out evaluation, and retain misses. These are proposed follow-ups, not newly tested or deployed integrations.

Before enabling decisions #

Label a representative OpenHands set independently, including missing references, ambiguous ownership, adversarial text, subtle races, benign installs, and multiple interests. Freeze the rubric, evaluate a fresh held-out set, measure recall and false positives per use case, and repeat near decision boundaries. Record model, rubric hash, immutable evidence revision, omissions, latency, cost, and the final verified outcome. A service error or missing evidence must produce a visible retry/review state, never a safety verdict.

The three examples are fully exercised at the API-to-local-decision boundary. Production collector completeness, account-level calibration, durable automation state, publication races, real vulnerability verification, and compaction task quality remain separate work. That boundary is the reason to start with observation and ranking.

Sources and interpretation #

Sources reviewed September 21, 2026. External findings and proposals are distinguished from our recorded OpenHands experiments.

Jev: model and API #

TypeSafe released Jev in early access on September 15, 2026. Our tests pin jev-1.13.0: text state in, typed Choice, Noul or Score answers out. Choice selects an option with a probability distribution; Noul estimates yes; Score rates ordered levels. It does not generate prose or directly read screenshots.

Documented limits: 64k tokens per request, 32k for state plus the longest question, 255 Choice options, and ten Score levels. Input costs $0.042 per million tokens; output is free. These are dated provider specifications, not measured capacity guarantees. Models and pricing · API · Primitives.

Typed output does not establish correctness. The vendor documents weaknesses with adversarial state, indirection and irrelevant context; its workflow comparisons use large-model consensus as reference labels. Launch · Limitations · Vendor evaluation.

Parcadei: six workflow notes #

The posts suggest skill selection, task-drift monitoring, retry assessment, and incident-driven skill improvement. Two further posts report option-order sensitivity under ambiguity and recommend a separate sufficiency question: unknown won 0/80 trials, while sufficiency stayed around 38.75–38.95%.

We retrieved post text through FxTwitter, without reproducing the original harness or screenshot data. Our 24-call adaptation found low sufficiency alongside confident Choices, but no order-driven label flip.

Anthus: confidence and calibration #

Ryan Porter’s analysis evaluates 8,801 constructed sentiment examples on Jev 1.13.0, with 5,280 calibration and 3,521 test examples. Reported Noul test ECE falls from 0.117 raw to 0.052 with Platt scaling and 0.008 with isotonic regression. These measure P(positive), not the API confidence field. Arbitrary neutral labels, one domain/model and repeated test-set comparisons limit transfer to OpenHands. We inspected the pinned source and metrics, not the full experiment.

Four quantities to keep separate #

QuantityMeaning in this workflowWhat to evaluate
Noul noulRaw estimate of yes for the exact proposition. A low value means no, not low certainty.Against independently adjudicated yes/no labels for that proposition. For a binary prediction at cutoff 0.5, the raw selected-label probability is max(p, 1-p).
Choice selected-label probabilityprobabilities[choice]; the quantity Anthus calls confidence in its correctness comparisons.Against whether the selected class is correct. Keep class-specific behavior visible for our multi-option ownership question.
API confidenceA distribution-derived statistic. Anthus observes approximately 2 * p_top - 1 for binary Choice.Do not interpret 0.8 as 80% accuracy or as an independent corroborating opinion. Do not extrapolate the binary formula to our four-option triage or Score.
Calibrated probabilityA fitted mapping for a defined target, rubric and population.Measure on held-out examples. Calibration of “this issue is actionable” does not establish calibration of “this entire automation is safe.”

Our own saved responses confirm the distinction: in all twelve binary Choices, the API confidence differs from 2 * p_top - 1 by at most 0.01 (within floating-point tolerance). One ambiguous case has top probability 0.96, API confidence 0.92, and a separate sufficiency Noul of 0.37. That is three different signals, not three estimates of correctness. This is an offline inspection, not twelve new calls and not a calibration test. Inspection script; recorded output.

Change to the recommendation: the raw 0.8 triage confidence gate and 0.5 Score confidence gate in the examples above are historical demonstration policies only. Neither is supported as an accuracy guarantee by our 35 fixture checks or by the Anthus sentiment results. Do not transfer the article’s favorable high-Noul bands into a security-approval threshold. Keep these workflows in observation/ranking mode until their own operating points are measured.

A metric boundary worth checking before reuse #

The pinned repository’s equal-width ECE implementation uses open-left bins, excluding predictions exactly equal to zero. Replaying that expression on probabilities [0, 1] with labels [1, 1] returns ECE 0; including zero in the first bin returns 0.5. The inspection script reproduces this isolated edge case. We have not quantified its effect on the published dataset; the separately reported Brier and log-loss improvements still provide evidence beyond that ECE figure. Include endpoints and bin counts when implementing our evaluator.

What this does not establish: isotonic calibration is not universally best, and a few hundred labels may be inadequate for rare security failures or narrow high-confidence bands. Calibration can improve the interpretation of a useful signal; it does not supply missing evidence, fix an incorrect target, or confer authorization.
