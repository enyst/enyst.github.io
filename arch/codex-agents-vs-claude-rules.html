Codex AGENTS.md is directory-scoped context, not Claude-style file-touch rules

Codex CLI and Claude Code both try to make repository instructions harder to miss. They choose different trigger seams: Codex starts from the active working directory; Claude rules, as described in the issue, start from the path of each touched file.

1.One-sentence answer

Codex CLI deterministically loads the AGENTS.md chain from project root to the active CWD, then relies on the model prompt to check deeper or outside-CWD AGENTS.md files; Claude Code rules are glob-based and fire on matching file operations.

Codex Directory boundary

AGENTS.md can appear in any directory. The scoped unit is that directory's subtree, with deeper files taking precedence by instruction.

Claude File path boundary

The issue describes .claude/rules/*.md files whose paths: globs are injected when matching files are read or edited.

2.The two trigger seams

Codex algorithm in plain English

  1. For each selected turn environment, Codex asks the environment filesystem for its CWD and calls read_agents_md. agents_md.rs:45-74
  2. It finds the project root by walking upward until a configured marker is found; default markers include .git. It does not walk past that root. agents_md.rs:1-16 147-199
  3. It searches directories from root to CWD and picks one candidate instruction file per directory. AGENTS.override.md wins over AGENTS.md, then configured fallbacks follow. agents_md.rs:201-235
  4. It reads non-empty files into ordered, model-visible instruction entries, truncating to project_doc_max_bytes. agents_md.rs:83-145
  5. The base prompt also tells the model that AGENTS.md files can appear anywhere, apply to their containing subtree, and must be checked when working below or outside the CWD. default.md:17-27

4.Gotchas that matter for SDK design

Codex is not a drop-in precedent for Claude rules. It proves directory-scoped instruction discovery is useful, but it does not implement a glob-based “inject when this file is read/edited/created” trigger.
  • Dynamic CWD refresh is nuanced. A Codex suite test has a TODO to diff user_instructions when AGENTS.md changes after CWD changes; the current snapshot asserts no refreshed AGENTS content in that case. model_visible_layout.rs:203-206 310-325
  • Remote/deferred environments still get deterministic project-doc loading once available. The remote environment test observes AGENTS content in later requests and records the loaded source. remote_env.rs:722-728
  • The SDK design implication is a hybrid. Codex-style directory memory maps naturally to repository context and plugin/package ownership; Claude-style path rules require a tool-use seam that evaluates paths on Read/Edit/Write and injects matched content deterministically.
