A controlled WhatsApp text canary needs a safe history handoff, explicit state isolation, and a verified agent-server with a real provider. Permanent replacement has a longer checklist.

Implemented foundation

Standalone WhatsApp and Discord bridges, shared durable Message Relay, per-chat routing, media ingestion and text delivery. WhatsApp has a deterministic test through the real TypeScript server and agent with a fake socket and test LLM. Test source.

Dated local observation: the legacy WhatsApp service was running during this audit, while the new server’s default :8790 endpoint had no listener. No live message or service swap was performed. These observations describe the audit window; they are not ongoing telemetry.

One execution core; channel reliability around it

The TypeScript SDK supplies the agent and provider clients. The separate TypeScript agent-server supplies the upstream-shaped API and conversation persistence. Bridges and the relay own platform intake, delivery and retries.

Three gates to a controlled text canary

01

Give history and state an explicit handoff

Owner: smolpaws-kxa.6 · before live text

The old process loads cursor progress from data/router_state.json. The new ledger looks in SQLite relay_state and defaults to sequence zero. It does not import the old JSON. Starting on the historical ledger can replay old messages.

Prove a stopped/drained baseline or import that preserves pending work, then prove rollback and re-cutover. Include duplicate legacy inserts, equal timestamps and late offline arrivals. Specify auth, ledger, one-chat allowlist, relay DB, server persistence and workspace separately.

SMOLPAWS_HOME_DIR moves WhatsApp state but currently does not move the relay database. The entrypoint needs explicit relay-path and startup-ping controls. A new relay DB can rediscover a lane’s old server conversation; isolation must include that server state. Keep one socket owner for the account.

Evidence: legacy JSON loading · new cursor reads · relay storage · entrypoint.

02

Verify the engine before opening a WhatsApp socket

Owner: smolpaws-kxa.7 · before live text

Re-vendor the merged SDK provider fix through the server’s runbook. Verify the clean build, exact server revision, profile, credential availability, tools and existing per-scope workspace. A local bundle patch or a healthy endpoint is insufficient proof of the intended deployment.

The new server uses its own profile state. Legacy LLM_PROFILE_ID does not select it, and the factory’s fallback tool set omits send_message. Configure that tool if the canary will test mid-turn delivery, then complete a real-provider tool call and continuation internally.

Evidence: agent factory · launcher health check · re-vendor runbook.

03

Run one bounded, trusted-chat text test

Owner: smolpaws-kxa.5 · after gates 01 and 02

Use an explicit allowlist containing the trusted control chat, a bounded live-send window and a tested rollback handoff. For the same account, stop/drain the legacy socket owner during the test and account for scheduled work. Suppress the automatic startup ping or include it in the agreed test.

Trace a unique input across every boundary below. Then test duplicate inbound replay, restart with queued outbound, and reconnection. Reconcile delivery_unknown; never blindly retry an ambiguous send.

  1. Inbound row exists in the WhatsApp ledger.
  2. Durable intake reaches done.
  3. The expected conversation has the user event and completed run.
  4. Expected mid-turn and/or final delivery rows exist.
  5. Delivery is done, with one send attempt and an external message ID.
  6. One correctly prefixed reply appears in the intended chat.

Acceptance contract: repository readiness plan. A visible reply alone is not a pass; a text pass does not prove full replacement.

Provider quirks have a home in the SDK

Python gets part of its provider compatibility from LiteLLM. Our TypeScript implementation owns that behavior directly. Keep protocol normalization inside each provider client and shared capability decisions in small pure helpers; keep those decisions out of the agent loop and channel bridges.

The merged tool-call fix accepts harmless extra fields such as DeepSeek’s index while validating required fields. Its fixture tests and the new provider guide make this a maintainable compatibility rule, even without a corresponding Python SDK diff.
