Agent Server bug tracker

Bugs found while building an executable feature map of the OpenHands Agent Server API (#5621). Each one is a known-bug bullet in the map, so the map reports it as an expected failure while it lasts and as an unexpected pass once it is fixed. The umbrella issue is #5653. Security findings are handled separately and are not listed here.

  • #5622highopen
    After a cipher key change, settings/secrets/profile writes answer 200 and null stored keys, not 409

    After the cipher key changes (new OH_SECRET_KEY, or a new session API key when it is unset), any write to settings, secrets or the active LLM profile answers 200 and rewrites values stored under the old key as null for good. The stores' "different key" guard never fires because undecryptable values load as None.

    F18.secret-key-rotation F20.secret-key-rotation
  • #5625mediumopen
    GET omits secrets added at create or via POST .../secrets until the next save; restart can drop them

    Secrets from the create body (secrets) or POST /api/conversations/{id}/secrets are applied to the live ConversationState in place, which skips the autosave. GET, search and batch get read the base_state.json snapshot, so they omit the secret until another change (a tags PATCH, a message) saves the state.

    F04.create-secrets-get F08.secrets-visible F08.secrets-unsaved-restart

GET /api/conversations/{id} reads that file, so a client that pauses and polls GET keeps seeing running.

  • #5633mediumopen

    When a conversation run fails, EventService._run_and_publish logs it with logger.exception(...) on the server's event loop.     /app-backends WebSocket bridge negotiates no subprotocol (expected the backend's choice, qa.v1)

    The Canvas App backend bridge (WS /app-backends/{name}/{path}) does not negotiate WebSocket subprotocols: the client's Sec-WebSocket-Protocol offer is not forwarded to the app's backend, and the bridge's 101 response selects none. Browsers fail such a handshake (Chrome: "Sent non-empty 'Sec-WebSocket-Protocol' header but no response was received"), so a Canvas App whose frontend uses a subprotocol (graphql-ws, many terminal protocols) cannot reach its backend over WebSocket.
