Feature Map Daily

Every day an agent checks the OpenHands Agent Canvas against its feature map: everything that changed since yesterday, driven in a real browser, with evidence. This page follows one daily pass, the one of 24 October 2026, and one change it verified from end to end: PR #18870, which stopped secret values from showing in plain text.

The map, and what a day covers

The verify-openhands feature map lists every behavior a user can see in the OpenHands app (Agent Canvas): 28 families, 798 behaviors after the 24 October pass. Each behavior has a stable ID such as F14.value-reveal and a recipe of control-openhands commands that an agent runs against a fresh local stack in a real browser.

Zoom in: F14, Secrets

F14 is one of the smaller families: Settings → Secrets, and the card the agent shows when it asks for a secret. After the 24 October pass it has 13 behaviors. One of them was written that day, because of #18870.

F14.value-reveal: the value field in the Add and Edit forms and in the request card is a masked password input. Its eye button (Show secret, then Hide secret) shows and hides only what was typed, never a stored value; it does not submit or save, and the field is masked again when the form reopens or another secret is edited.

The commands, as pseudocode

Every line is a real control-openhands verb. The outer loop is the daily pass; the inner block is the F14.value-reveal recipe, abridged.

# a daily delta pass (verify-openhands)
BASE     = map baseline                     # "Maintenance baseline: main@<sha>" in the map index
TARGET   = git rev-parse origin/main
families = map affected --base BASE --target TARGET   # → F01 F03 F05 F06 F07 F14 F25 F26
RUN      = launch --new ; doctor             # isolated stack: Agent Server, automation, UI, browser
llm preset deepseek ; onboard --skip

for row in rows(families) + rows_linking_closed_issues:
    # F14.value-reveal, abridged
    browser goto   /settings/secrets
    browser click  testid=add-secret-button
    browser eval   "input.tagName, input.type, input.autocomplete"   # INPUT password new-password
    browser fill   'testid=add-secret-form >> testid=value-input'  qa-dummy-value-123
    browser network --clear
    browser click  'testid=add-secret-form >> role=button[name="Show secret"]'
    browser eval   "input.type"                                       # text, button now "Hide secret"
    browser network --filter /api/settings/secrets                    # no request: nothing saved
    browser screenshot --feature F14.value-reveal --name revealed
    evidence add --feature F14.value-reveal --result pass --artifact evidence/F14.value-reveal/revealed.png

for block in bug list:
    bug run block.id --attempts 2                                     # xfail: still broken · xpass: review the row

evidence report                              # pass / fail / blocked / not-run / xfail / xpass, fail rows first
map check ; map coverage ; map testids       # the map stays well-formed
map baseline --set TARGET                    # proposed in the one PR; merging accepts it
stop

The before/after recordings used browser record start --feature F14.value-reveal --name settings-before --fps 20 … browser record stop on each stack. The full recipe is in F14-secrets.md; the procedure is in daily.md.
