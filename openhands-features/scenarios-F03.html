Entry points & prerequisites

What this family covers

Home is the "What do you want to work on?" screen at / and /conversations. A Code / Automate toggle above the composer picks what a submit starts: a coding conversation, or an automation setup conversation where the agent fills an automation form. A user describes a task in the composer and, on a local backend, can first pick a workspace folder (Open Workspace, folder browser, Manage Workspaces), a workspace mode and plugins; submitting creates a conversation and opens it. A warning banner replaces a silent failure when no LLM is configured. Below the composer, home offers recommended automations, a pinned-automations grid and an activity list of enabled automations with per-item actions.

How a user gets here

  • Sidebar New Chat (sidebar-conversations-link), which opens /conversations; the logo does the same (see F02).
  • Direct URL / (unless a page is pinned as home, see F02) or /conversations.
  • Command menu (Control+k, Meta+k or command-menu-trigger): search "New chat", choose New chat.
  • Above the composer: the Code / Automate toggle (home-launcher-mode-code, home-launcher-mode-automate).
  • Under the composer: Open Workspace (open-workspace-button) or, once confirmed, the preview bar (home-git-control-bar-preview); Plugins (open-plugin-picker).
  • In the Open Workspace dialog: the combobox (workspace-dropdown) and its footer + Add Workspace (add-workspaces-button) and Manage Workspaces (manage-workspaces-button, shown once any workspace or parent exists); in Add workspaces, the Favorites/Locations sidebar (folder-browser-sidebar-<name>).
  • Below the composer: recommended cards (recommended-automation-rail-card-<id>), pinned cards (pinned-automation-card-<id>) and rows (running-automation-row-<id>) with their kebabs; + Add (home-automations-manage).

Before you start

Use an OpenHands checkout at the source revision, with Node 24+, installed npm dependencies, uv / uvx, and a supported Chromium browser. The verification skill is the complete setup contract.

export PATH="$PWD/.agents/skills/verify-openhands/scripts:$PATH"
export OH_VERIFY_RUN=$(control-openhands launch --new --print-run)
control-openhands doctor
control-openhands onboard --skip
# Configure a model only for a scenario that needs one:
control-openhands llm preset deepseek
# When the run is complete:
control-openhands stop

F01 walks onboarding instead of skipping it. No-model checks run before model configuration. Keep OH_VERIFY_RUN set so commands address your own run. Desktop is 1440 × 1000; phone is 390 × 844. Model-backed checks need the configured provider key and budget.

Recipes run in source order within each family and can share fixtures. The page preserves that order; “as above” is a dependency on an earlier case. Setup commands and API writes arrange state. They do not prove a UI path. Follow the family cleanup steps.

A known failure preserves the intended expectation beside the observed defect. Executable known-bug blocks use xfail for a reproduced symptom and xpass when it stops reproducing.
