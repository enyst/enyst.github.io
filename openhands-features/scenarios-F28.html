13 behaviors · 11 scripts & contracts · Maintained source

Entry points & prerequisites

What this family covers

The setup page is the one form for making and changing automations outside the template dialog. Add Automation → Create Automation opens it blank at /automations/setup; a saved draft reopens at /automations/setup?draftId=<id>; kebab Edit opens an existing automation at /automations/setup?automationId=<id>. The form collects Name, a Prompt (or Custom Python with entrypoint and setup script), agent profile, model and repositories, a Schedule or Event trigger, and optional plugins and timeout. A docked composer under the form can ask the agent to fill it. Create mode's toolbar has Save draft, Test and Create Automation; edit mode's has Test, Save and Close. A server-backed draft carries the server's validation result and test runs; Create turns it into a real, enabled automation and removes the draft.

F22 keeps F22.agent-assisted-setup (the end-to-end agent, plugin, phone and draft-Test recipes); F23 owns edit mode (F23.edit-*, including Test and the save state on the edit page). This family gives each create-mode behavior its own ID so a pass can fail one without failing the others.

How a user gets here

  • Dashboard header Add Automation → Create Automation (automations-add-automation, then automations-add-automation-create): blank create mode. Every create recipe below starts here.
  • Empty dashboard Create Automation (automations-empty >> automations-create-automation): the same blank form (F21.empty-state).
  • Dashboard Drafts group: name or Resume (automation-setup-draft-resume-<draft-id>) and the pencil (Edit, automation-setup-draft-edit-<draft-id>) open ?draftId=<id>.
  • Kebab Edit on a dashboard card or the detail page header: edit mode (?automationId=<id>, F21.edit, F23.edit-open).
  • A direct URL with draftId or automationId (see the cold-load gotcha).

Given

Preconditions:

  • Baseline state (launch, doctor, onboard --skip). No LLM is needed: every bullet uses the Custom Python kind or never dispatches, and the agent-assisted path stays in F22.
  • Desktop viewport; the F28.error-contrast bullet switches color themes (Settings → Application, F16) and restores the default.
  • Every recipe below was run as written on 2026-10-15 on a fresh local control-openhands launch of main with Agent Server 1.54.0 and no LLM. Documented known failures remain failures.

Family notes, prerequisites for known issues & limits
  • A toast can cover the toolbar (Save draft, Test, Close) and stays while the pointer rests on it, so the next toolbar click times out ("subtree intercepts pointer events"). After each save, browser hover a form field (for example testid=automation-setup-name) before clicking the toolbar again, as F22's Gotchas say.
  • Drive inputs with browser fill: setting .value from browser eval does not reach React state for every field, and a save then sends the old value.
  • Change one field per Save draft when checking a validation message: a save shows only the first server error, so two edits in one save hide the second.
  • A cold load of /automations/setup?draftId=<id> or ?automationId=<id> (a reload or a typed URL) opens the form: re-checked 2026-10-14 on a control-openhands launch of main with this family (both read their Name back). An earlier instance of unknown build stayed on Loading saved draft… for more than 20 s; if that returns, compare with opening the same draft from the dashboard.
  • The draft bar duplicates the prompt error: Field required appears both under Prompt and in the bar.
  • Kebab Edit on a Custom Python automation shows the code editor instead of the saved bundle summary: open bug #18341 (F23), with fixes in PRs #18353 and #18444.
  • Escape on the setup page does nothing, by design (F23.edit-close).

Before you start

Use an OpenHands checkout at the source revision, with Node 24+, installed npm dependencies, uv / uvx, and a supported Chromium browser. The verification skill is the complete setup contract.

export PATH="$PWD/.agents/skills/verify-openhands/scripts:$PATH"
export OH_VERIFY_RUN=$(control-openhands launch --new --print-run)
control-openhands doctor
control-openhands onboard --skip
# Configure a model only for a scenario that needs one:
control-openhands llm preset deepseek
# When the run is complete:
control-openhands stop

F01 walks onboarding instead of skipping it. No-model checks run before model configuration. Keep OH_VERIFY_RUN set so commands address your own run. Desktop is 1440 × 1000; phone is 390 × 844. Model-backed checks need the configured provider key and budget.

Recipes run in source order within each family and can share fixtures. The page preserves that order; “as above” is a dependency on an earlier case. Setup commands and API writes arrange state. They do not prove a UI path. Follow the family cleanup steps.

A known failure preserves the intended expectation beside the observed defect. Executable known-bug blocks use xfail for a reproduced symptom and xpass when it stops reproducing. Cloud accounts, enterprise capabilities and other unavailable prerequisites remain explicit. “Not run” is different from “blocked”.
