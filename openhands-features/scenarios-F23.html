41 behaviors · 34 scripts & contracts · Maintained source

Entry points & prerequisites

What this family covers

The detail page (/automations/<id>) shows one automation: a Back to Automations link, a header with the name, an Active/Inactive badge, Run now, an on/off switch and a kebab (Export, Tarball, Edit, Turn on/off, Delete); a Why this is paused banner when it was turned off; the Prompt (or, for a script automation, the Script bundle); Configuration (repositories, trigger, schedule or event source/type/filter, LLM profile); a Plugins card when it has plugins; an Activity card (Created, Last run); and the Activity Log of runs with status, summary, cost, a logs dialog, a link to each run's conversation and JSON/CSV export. Kebab Edit opens the setup page in edit mode (/automations/setup?automationId=<id>, since #17688), which changes name, prompt, agent and LLM profile, timeout and the trigger. A DRAFT-state test automation (materialized by a draft Test, F21.saved-drafts) shows a Draft badge and no on/off switch.

How a user gets here

  • Dashboard (/automations, F21): click a card's heading, a list row link, or the kebab Automation actions → View; a sparkline bar opens /automations/<id>?run=<runId> (F21.sparkline-deeplink).
  • Direct URL /automations/<id> and /automations/<id>?run=<runId>. Get <id> from control-openhands browser url after opening a card, or from control-openhands api GET /api/automation/v1; get <runId> from control-openhands api GET /api/automation/v1/<id>/runs.
  • Edit: the detail kebab Edit (exercised here) and the dashboard kebab Edit (F21.edit) both open /automations/setup?automationId=<id>; a cold load of that URL opens it too.
  • Browser Back from a run's conversation returns to the detail page.
  • The detail page has no command-menu entry and no keyboard shortcut.

Canvas's frontend log reader does not send that filter, but automation launch preparation and prompt/plugin preset repository clones use (Async)RemoteWorkspace.execute_command, whose output poller does. Recheck a bounded genuine preset/setup or repository-clone command that emits enough chunks to cross the 100-event boundary, correlating its final BashOutput and real run result; a frontend Logs read or a one-output command does not cover the incremental branch.

If that same conversation is already running a tool for more than 30 s, the join request can time out and fail the automation worker while the agent continues. Recheck an owned continued-conversation automation with a genuine already-running long tool and correlate worker error, agent status and final run result; a fresh conversation or one normal first run() does not exercise the join. No model execution is authorized in this pass.

Known issue OpenHands/software-agent-sdk#5938 (F23.run-status-polling): prompt/plugin preset workers register an event callback that forwards ActionEvent.summary as the live phase. After an events-socket reconnect, REST-reconciled events reach SDK state but are not replayed to that callback, so summaries emitted in the gap can be missed. Recheck an owned real preset worker through a bounded reconnect window while a genuine action is recorded; compare callback-driven phase with stored events. Current Canvas phase rendering has its separate #17121 gap, and the worker's completion metadata is not claimed lost merely because this callback missed an event.

Before you start

Use an OpenHands checkout at the source revision, with Node 24+, installed npm dependencies, uv / uvx, and a supported Chromium browser. The verification skill is the complete setup contract.

export PATH="$PWD/.agents/skills/verify-openhands/scripts:$PATH"
export OH_VERIFY_RUN=$(control-openhands launch --new --print-run)
control-openhands doctor
control-openhands onboard --skip
# Configure a model only for a scenario that needs one:
control-openhands llm preset deepseek
# When the run is complete:
control-openhands stop

F01 walks onboarding instead of skipping it. No-model checks run before model configuration. Keep OH_VERIFY_RUN set so commands address your own run. Desktop is 1440 × 1000; phone is 390 × 844. Model-backed checks need the configured provider key and budget.

Recipes run in source order within each family and can share fixtures. The page preserves that order; “as above” is a dependency on an earlier case. Setup commands and API writes arrange state. They do not prove a UI path. Follow the family cleanup steps.

A known failure preserves the intended expectation beside the observed defect. Executable known-bug blocks use xfail for a reproduced symptom and xpass when it stops reproducing. Cloud accounts, enterprise capabilities and other unavailable prerequisites remain explicit. “Not run” is different from “blocked”.
